## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Worktree node_modules not shared | After Wave 1 merge, `next-intl` was in the committed package.json/lockfile but absent from the main tree's `node_modules` (installed only inside the executor's worktree). The post-merge production build failed with `Cannot find module 'next-intl/plugin'`. | advisory | After any worktree merge that changes package.json/package-lock.json, run `npm install` in the main tree BEFORE the post-merge build. |
| Metadata spread vs nest | `generateMetadata` used `...buildHreflangAlternates('/')`, spreading `{canonical, languages}` to the top level of the Metadata object where Next.js silently drops them (only the `alternates:` key is processed). Title/description rendered; all hreflang links were absent. | advisory | Assign the helper result to `alternates:`, never spread it. Also set `metadataBase` (a `URL`) so absolute-URL alternates resolve. |
| Stale .next type artifacts | After the flat→[locale] layout restructure, a cached `.next/dev/types/validator.ts` referenced the deleted `app/layout.js` and typed-route `/` conflicts, failing the build. | advisory | `rm -rf .next` before the post-merge build when file structure (routes/layouts) changed. |
