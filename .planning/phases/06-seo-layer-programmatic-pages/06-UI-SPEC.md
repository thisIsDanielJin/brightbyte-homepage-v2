# Phase 6 — UI Design Contract: SEO Layer & Programmatic Pages

> Visual and interaction contract for `app/[locale]/s/[slug]/page.tsx` and the SeoPageLayout component.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Phase character:** Primarily data-plumbing. Only ONE new user-facing surface: the 25-page
> SEO landing layout (D-06). All other deliverables (schema enrichment, migration script,
> sitemap/robots, JSON-LD, hreflang) produce zero visible UI. The design contract below
> governs the SEO landing layout only. Everything else is backend/build-time.

Exceptions:

- **44px touch-target minimum on FAQ accordion trigger** — enforced via `min-h-[44px]`.
  This is the WCAG 2.5.5 minimum touch-target size, an accessibility requirement inherited
  from the Phase 4 interactive-control baseline. It is explicitly exempt from the 4-multiple
  spacing-grid constraint — 44px is not a 4-multiple by design. Do NOT round up to 48px; that
  would silently regress the documented Phase 4 accessibility baseline. Re-verification of
  this value against the spacing grid is out of scope for Phase 6.

- Primary CTA button fill (`bg-accent`, `hover:bg-accent-hover`)

- 30% secondary: `bg-surface-subtle` on alternating bands (benefits section, FAQ section)
- 10% accent: primary CTA, ✓ checkmarks, focus rings — never painted in large areas

**New component required: `SeoPageLayout`**
File: `components/seo/SeoPageLayout.tsx`
Type: RSC (Server Component) — receives pre-fetched page data; no client state needed except
the FAQ accordion sub-component.

**FAQ accordion interaction:**
The existing codebase has no reusable FAQ accordion component (v1's FAQAccordion lived in
`components/ui/FAQAccordion/` but this is v1). Phase 6 builds a new, minimal accordion as a
`'use client'` sub-component within `components/seo/SeoPageLayout.tsx` (or extracted to
`components/ui/FaqAccordion.tsx`). Pattern: `<details>/<summary>` with CSS transition, OR
a minimal React state toggle. Both are acceptable; `<details>/<summary>` is preferred for
zero-JS fallback.

**Accordion interaction spec:**
- Trigger: `<summary>` or button — `text-base font-medium text-primary`, full-width, `min-h-[44px]`
- Icon: inline SVG chevron, rotates 180° on open (`[transition-duration:150ms]`)
- Panel: `text-base text-secondary leading-[1.6]`, collapses via CSS `max-height` transition or `<details>`
- Border: `border-b border-border` between items
- Active panel background: `bg-surface-muted`
- Only one panel open at a time is acceptable; multiple open simultaneously is also fine
  (choose whichever is simpler — no business requirement for exclusive open)

## SeoPageLayout — Layout Specification

The SEO landing page template follows a linear vertical rhythm:
**Header (shared) → Hero → Benefits → FAQ → Trust Metrics → CTA → Footer (shared)**

Trust metrics are optional (only rendered when `trustMetrics[]` is non-empty).

### Band 1: Page Hero

Container: `MotionSection` + `py-24 px-4 md:px-8 lg:px-16 bg-surface`

Layout:
- Desktop (md+): `grid grid-cols-1 lg:grid-cols-[1.2fr_1fr] gap-16 items-center max-w-7xl mx-auto`
- Mobile: single column

Left column (copy):
- Category badge: `text-sm font-medium text-secondary uppercase tracking-widest` — pill with
  `border border-border rounded-full px-3 py-1`, `mb-6`
- `<h1>`: `text-4xl md:text-5xl font-bold text-primary leading-[1.1] mb-6` — maps to `heroHeadline`
- Body paragraph: `text-base text-secondary leading-[1.6] max-w-[520px] mb-8` — maps to first
  paragraph of `heroSubtext`
- Primary CTA button: `bg-accent text-surface text-sm font-medium px-6 py-3 rounded-sm
  hover:bg-accent-hover [transition-duration:150ms] [transition-timing-function:var(--ease-standard)]
  transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent
  focus-visible:ring-offset-2 active:scale-[0.98]`
  — label from Sanity `ctaText` field; links to homepage `#contact` anchor: `href="/{locale}#contact"`

Right column (image, desktop only):
- `hidden lg:block` wrapper
- `aspect-ratio: 4/3`, `rounded-sm overflow-hidden relative`
- `<Image>` with `fill`, `object-cover`, `sizes="(max-width: 1024px) 0px, 40vw"`
- Source: slug-keyed static image from `/images/seo/{slug}.jpg` with category fallback
  `/images/seo/{category}.jpg`; if neither exists, omit the right column entirely
  (do NOT render a broken image placeholder)

### Band 2: Benefits Grid

Container: `MotionSection` + `py-24 px-4 md:px-8 lg:px-16 bg-surface-subtle`

Section header (eyebrow only, no H2):
- `text-sm font-medium text-secondary uppercase tracking-widest mb-8`
- DE: "So hilft BrightByte" / EN: "How BrightByte helps" (hardcoded copy — these are
  structural labels, not CMS-managed, consistent with Phase 4's eyebrow pattern)

Grid: `grid grid-cols-1 sm:grid-cols-2 gap-4 max-w-5xl mx-auto`

Each benefit card:
- `bg-surface border border-border rounded-sm p-6 flex items-start gap-4`
- Check icon: `<span className="text-accent font-medium mt-0.5 flex-shrink-0" aria-hidden="true">✓</span>`
- Benefit text: `text-base text-primary leading-[1.5]` — maps to `benefits[].text`

### Band 3: FAQ Accordion

Container: `MotionSection` + `py-24 px-4 md:px-8 lg:px-16 bg-surface`

Section header:
- Eyebrow: `text-sm font-medium text-secondary uppercase tracking-widest mb-2`
  DE: "Häufige Fragen" / EN: "Frequently asked questions"
- `<h2>`: `text-4xl font-semibold text-primary mb-8`
  DE: "Ihre Fragen beantwortet" / EN: "Your questions answered"

Accordion container: `max-w-3xl mx-auto space-y-0` — items are vertically stacked with dividers

Each FAQ item:
- `border-b border-border last:border-b-0`
- Trigger: `flex items-center justify-between w-full text-left py-4 px-0 text-base font-medium
  text-primary min-h-[44px] focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent
  focus-visible:ring-inset` — maps to `faqs[].question`
- Chevron icon: inline `<svg>` (24×24), `[transition:transform_150ms_var(--ease-standard)]`,
  rotates 180° when panel open
- Answer panel: `text-base text-secondary leading-[1.6] pb-4 pt-1` — maps to `faqs[].answer`

### Band 4: Trust Metrics (conditional — render only when `trustMetrics[]` is non-empty)

Container: `MotionSection` + `py-16 px-4 md:px-8 lg:px-16 bg-surface-subtle`

Layout: `grid grid-cols-2 sm:grid-cols-3 gap-8 max-w-3xl mx-auto text-center`

Each metric:
- Value: `text-4xl font-bold text-primary` — maps to `trustMetrics[].value`
- Label: `text-sm font-medium text-secondary mt-2` — maps to `trustMetrics[].label`

### Band 5: CTA Strip

Container: `MotionSection` + `py-24 px-4 md:px-8 lg:px-16 bg-surface text-center`

Layout: single centered column, `max-w-xl mx-auto`

Elements:
- `<h2>`: `text-4xl font-bold text-primary mb-4`
  DE: "Bereit loszulegen?" / EN: "Ready to get started?"
- Body: `text-base text-secondary leading-[1.6] mb-8`
  DE: "Lassen Sie uns über Ihr Projekt sprechen. Unverbindlich und kostenlos."
  EN: "Let's talk about your project. No commitment, no cost."
- Primary CTA button: same spec as Band 1 CTA (`bg-accent` filled)
- Trust ticks: `flex justify-center gap-6 flex-wrap mt-6`
  — three items: `text-sm text-secondary`
  DE: ["Festpreis", "Unverbindlich", "Antwort in 24h"]
  EN: ["Fixed price", "No obligation", "Reply in 24h"]
  (hardcoded structural copy — matches v1 pattern; not CMS-managed)

## Phase-Specific Constraints

These constraints apply specifically to Phase 6 and must not be relaxed:

1. **Token discipline (IDENT-01):** Zero raw hex values in `SeoPageLayout` or any new component.
   Zero `text-gray-*` utilities. All color via named semantic token utilities (`text-primary`,
   `bg-surface-subtle`, `text-accent`, etc.).

2. **stega discipline (CMS-03):** `stega: false` is a hard invariant on `lib/sanity/client.ts`.
   No new Sanity client created without this flag. Applies to all new queries in this phase.

3. **No inline styles:** v1's `SeoPageContent.tsx` uses hardcoded hex inline styles throughout.
   v2's `SeoPageLayout` uses zero inline styles — everything via Tailwind utility classes consuming
   `@theme` tokens. This is the explicit design-bar requirement from D-06.

4. **`dangerouslySetInnerHTML` for JSON-LD only:** The `<script type="application/ld+json">` pattern
   is the only acceptable use of `dangerouslySetInnerHTML` in this phase. All other content
   renders via React JSX. No user-controlled data reaches `dangerouslySetInnerHTML` paths.

5. **No new npm packages:** Phase 6 adds zero new dependencies. All UI is built from the
   existing stack (Next.js 16 + Tailwind v4 + existing components).

6. **Reduced motion:** All `MotionSection` wrappers carry the project-wide `prefers-reduced-motion`
   reset from `globals.css` (zero duration on all transitions). No additional motion guards needed
   per section — the global reset handles it.

7. **Bilingual copy discipline:** All structural labels (eyebrows, CTA headings, trust ticks)
   must use a locale ternary or `useTranslations` — never raw German strings without an EN
   equivalent. The `app/[locale]/s/[slug]/page.tsx` is a Server Component — use
   `getTranslations(locale)` (server variant), not `useTranslations()`.
