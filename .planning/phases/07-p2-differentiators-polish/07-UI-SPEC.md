# Phase 7 — UI Design Contract: P2 Differentiators & Polish

> Visual and interaction contract for Phase 7 frontend work. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Context:** Phase 7 layers conversion-improving sections onto a complete, live site. All new sections extend the visual system already established in Phase 1 and implemented through Phases 4–6. The token system is in `styles/tokens.css`; the `MotionSection` pattern is established in `components/ui/MotionSection.tsx`. No new design tokens are introduced; this spec prescribes how Phase 7 components consume what already exists.

## Spacing Scale

All spacing consumes the `@theme` tokens from `styles/tokens.css`. No new tokens are introduced.

| Token | Value | Usage |
|-------|-------|-------|
| `--spacing-1` | 4px | Icon gaps, inline nudges |
| `--spacing-2` | 8px | Compact element spacing, icon-to-label |
| `--spacing-4` | 16px | Default element spacing, card internal padding |
| `--spacing-6` | 24px | Card internal padding, grouped item gaps |
| `--spacing-8` | 32px | Component-level gaps |
| `--spacing-12` | 48px | Section-internal block spacing |
| `--spacing-16` | 64px | Section padding desktop (small sections — e.g. guarantee strip, case studies bridge) |
| `--spacing-24` | 96px | Section padding desktop (standard — py-24 for all new sections) |

> **Project-level extensions:** 96px (`--spacing-24`) and 128px (`--spacing-32`) are section-rhythm extensions established in Phase 4, not component-level spacing tokens. 128px is not used in Phase 7 sections.

Exceptions: Touch targets on accordion summaries and interactive controls minimum 44px height (WCAG 2.5.5 — already established in `FaqAccordion.tsx`).

**Section vertical rhythm:** All new sections use `py-24 px-4 md:px-8 lg:px-16` unless noted. This matches all existing Phase 4 sections.

**Max-width container:** `max-w-5xl mx-auto` for standard sections. `max-w-3xl mx-auto` for single-column prose (FAQ, Process). Case study page content well: `max-w-4xl mx-auto`.

## Page Structure: New Pages

### Case Study Pages — `app/[locale]/work/[slug]/page.tsx`

Each case study page is a full Next.js App Router RSC page. Structure:

```
Header (sticky, from layout.tsx)
  └── <main>
        ├── Band 1: Hero — client name, category badge, outcome metric callout, brief descriptor
        ├── Band 2: Problem — what the client's situation was before
        ├── Band 3: Solution — what BrightByte built and how
        ├── Band 4: Outcome — measured result (tied to testimonials metric)
        └── Band 5: CTA strip — "Ähnliches Projekt?" / "Similar project?" + contact link
Footer (from layout.tsx)
```

Each band is wrapped in `<MotionSection>` with the standard `py-24 px-4 md:px-8 lg:px-16` rhythm.

### Homepage New Sections (added to `app/[locale]/page.tsx`)

Section insertion order (extending the D-05 order):
```
Hero → Services → Pricing → Work → Case Studies CTA Bridge → Testimonials → Process → Guarantee → FAQ → About → Contact
```

- **Case Studies CTA Bridge:** a lightweight band with a single CTA linking to the three case study pages. Sits between Work grid and Testimonials. Not a data-fetched section — static copy + three anchor cards.
- **Process:** 3-step horizontal/vertical layout. `bg-surface-subtle`.
- **Guarantee:** centered strip. `bg-surface-muted`. Single headline + body + three trust ticks.
- **FAQ:** accordion using the existing `FaqAccordion` component. `bg-surface`.

## Section-by-Section Interaction Contracts

### Case Study Hero Band

- Left column: category pill (`border border-border rounded-full px-3 py-1 text-sm uppercase tracking-widest text-secondary`) + H1 (`text-4xl md:text-5xl font-bold text-primary leading-[1.1]` — `md:text-5xl` is a responsive modifier of the Heading role, not a distinct type role) + outcome metric callout (`text-4xl font-bold text-primary`) + metric label (`text-sm text-secondary`) + short descriptor (`text-base text-secondary leading-[1.6]`)

- Outcome band includes the metric callout: `text-4xl font-bold text-primary` value + `text-sm text-secondary` label — same pattern as `TestimonialsSection.tsx`

## Motion Contract

**All new sections use `MotionSection`** — the existing `components/ui/MotionSection.tsx` wrapper with no modification.

Motion parameters (from `MotionSection.tsx`, no changes):
- `initial: { opacity: 0, y: 10 }` — 10px rise, fade from 0
- `whileInView: { opacity: 1, y: 0 }` — once, at `amount: 0.15` viewport intersection
- `transition: { duration: 0.5, ease: [0.0, 0.0, 0.2, 1] }` — matches `--ease-out` and `--duration-entrance`
- Reduced motion: `duration: 0` (instant) when `prefers-reduced-motion: reduce` is set

**Phase 7 motion refinement scope (SC #4):** Final review pass ensures all existing sections also comply with these exact values. The D-11 hero fade-in bug is fixed in this phase — the `HeroCanvas` wrapper must receive the `opacity-0 data-[ready=true]:opacity-100` transition correctly. Fix approach: give the wrapper a stable DOM key or restructure the sibling ordering to prevent React reuse of the `hero-backdrop` class node.

**Stagger:** No stagger animation on Process steps or case study bands. Each `MotionSection` fires independently on viewport entry. This preserves the "whisper-quiet" identity — stagger would feel choreographed and startup-flashy.

**Accordion open/close:** The chevron rotation in `FaqAccordion.tsx` already uses `transition-transform duration-150 ease-[var(--ease-standard)]`. No change needed.

## Accessibility Contract

Building on the Phase 4 QA-03 baseline. Phase 7 success criterion SC #3 requires zero axe-playwright violations across all pages including new routes.

- All case study pages include a visible skip-link (`<a href="#main-content">`) consistent with existing pages
- Work grid card links: `aria-label="Fallstudie {title} anzeigen"` / `aria-label="View case study for {title}"` on the wrapping `<Link>` (card has no visible "read more" text — label is required)
- Process step number chips: `aria-hidden="true"` on the visual number chip; step title conveys the step identity in the accessible tree
- Guarantee trust ticks: `aria-hidden="true"` on the `✓` character; the full tick text (`text-sm text-secondary`) carries the meaning
- FAQ accordion: existing `<details>/<summary>` pattern preserves native AT disclosure semantics — no change needed
- All focus-visible rings: `focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2 focus-visible:outline-none` (established pattern — copy exactly from `SeoPageLayout.tsx` CTA_CLASS and `FaqAccordion.tsx`)
- Minimum touch target: 44px height on all interactive elements (established via `min-h-[44px]` on accordion summary)
- `prefers-reduced-motion`: `MotionSection` handles this globally with `duration: 0`. The hero fade-in fix must also respect reduced motion — apply no transition when `useReducedMotion()` returns true.

## Implementation Notes for Executor

1. **Token discipline (IDENT-01):** Zero raw hex values, zero `text-gray-*` utilities in any new file. All color via named semantic utilities (`text-primary`, `bg-surface-muted`, etc.). Violations will fail the token-audit page invariant.

2. **Sanity schema additions:** Phase 7 requires Sanity schema additions for (a) case study fields on the `project` document type and (b) FAQ/Process/Guarantee content on `siteSettings` or a new top-level document. The planning phase must decide whether FAQ/Process/Guarantee are CMS-driven (Sanity) or static (message dictionaries). Given the identity of the content (rarely changes, editorial precision matters), **Process and Guarantee are static in message dictionaries**. **FAQ is Sanity-driven** (5–7 questions likely authored and iterated in Studio). Case study content (problem/solution/outcome text, hero image) is Sanity-driven.

3. **Route structure for case studies:** `app/[locale]/work/[slug]/page.tsx` with `generateStaticParams` pulling project slugs from Sanity. Consistent with the SEO programmatic pages pattern at `app/[locale]/s/[slug]/page.tsx`.

4. **Hero fade-in fix (D-11):** The `HeroCanvas` wrapper div must receive a stable `key` or restructured JSX to prevent React's reconciler from reusing the adjacent `hero-backdrop` sibling node. The transition class `opacity-0 [transition:opacity_500ms…] data-[ready=true]:opacity-100` must apply to the wrapper that receives `data-ready=true`. Verify with a `data-testid="hero-canvas-wrapper"` and `expect(wrapper).toHaveAttribute('data-ready', 'true')` in Playwright.

5. **Header nav update:** Phase 7 does not add new anchor sections to the main nav. The Header `NAV_SECTIONS` array (`['services', 'pricing', 'work', 'contact']`) remains unchanged — the new sections (FAQ, Process, Guarantee) are discovery content, not primary nav destinations.

6. **No new motion variables:** Do not add motion tokens. All animation uses the existing `--ease-out`, `--duration-entrance`, `--duration-standard`, `--duration-micro` tokens via `MotionSection` or inline arbitrary values `[transition-duration:var(--duration-standard)]`.
