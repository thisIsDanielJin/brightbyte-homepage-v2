# Phase 3 Plan 2: Full schema set + singleton + image builder + query layer Summary

Added the four remaining Sanity document types (`project`, `testimonial`, `seoPage`, `siteSettings`) on the Wave 1 tracer's proven patterns, enforced `siteSettings` as a structure-builder singleton, wired the `@sanity/image-url` builder, and completed the centralized `$locale`-parameterized typed GROQ query set (7 queries) that Phase 4 imports — delivering CMS-01 (five doc-i18n types) and extending CMS-03 (full typed query layer). All five types are DE/EN document-internationalized; `npm run build` and `tsc --noEmit` are green.

## What was built

- **project** — per-locale slug (D-11), hotspot image (for `urlFor`), `outcomeNote` (SEC-04), `order`.
- **testimonial** — `quote`/`author`/`company` + separate inline `outcomeValue`/`outcomeLabel` metric (D-06).
- **seoPage** — per-locale slug (D-11), Portable Text `body` (the one genuine long-form field, D-04), `metaDescription` — shaped for Phase 6.
- **siteSettings** — singleton: `siteTitle`, `navLabels`, `footerText`, `contactEmail`, `address`, `steuernummer`, `vatNote`, `defaultSeo`; Impressum/legal values from `freelancer.md` (SEC-09 shape).
- **Singleton enforcement (D-07 / T-03-05)** — `structure.ts` pins `documentId('siteSettings')` as a single list item and filters it from the generic list; `sanity.config.ts` `document.actions` strips `duplicate`/`delete`/`unpublish` for the type.
- **i18n enrollment (D-08)** — `documentInternationalization.schemaTypes` now lists all five: service, project, testimonial, seoPage, siteSettings.
- **lib/sanity/image.ts** — `urlFor(source)` from `imageUrlBuilder(client)`, typed with `SanityImageSource`, reusing the single read client (no second `createClient`).
- **Query layer** — `PROJECTS`/`PROJECT_BY_SLUG`/`TESTIMONIALS`/`SEO_PAGES`/`SEO_PAGE_BY_SLUG`/`SITE_SETTINGS` `defineQuery`-wrapped, every one filtering `language == $locale` (D-10); slug lookups add `$slug` (D-11); `siteSettings` queried via `language`, not the fixed id. 7 queries typed by typegen.

## Deviations from Plan

### Auto-resolved checkpoints (autonomous mode)

Re-confirming would be redundant. Proceeded with the build; no user input needed.

### Auto-fixed issues

**2. [Rule 2 — missing critical functionality] Required `language` field on every doc-i18n type**
- **Found during:** Task 03-02-07 (schema-extract gate). `sanity schema extract` showed NO `language` field on any of the five types, including Wave 1's already-enrolled `service`.
- **Root cause:** Wave 1's tracer assumed `@sanity/document-internationalization` *injects* the `language` field. The plugin README ("Language field") is explicit: each enrolled type **must declare** a `string` field matching `languageField` (default `language`); the plugin only *writes patches* to it. Without it, doc-i18n does not function and CMS-01's extract check fails.
- **Fix:** Added a `readOnly: true, hidden: true` `language` string field to `service`, `project`, `testimonial`, `seoPage`, `siteSettings`, and corrected the misleading JSDoc in each. Re-extracted (all five now show `language`), regenerated types, rebuilt.
- **Files modified:** all five schema type files + `sanity.types.ts`.
- **Commit:** 2822e23
