# Plan 03-03 — Canonical content seed + structural guards + build verification

## Goal

Author the canonical BrightByte content into Sanity as the single source of truth (CMS-02), and lock in the CMS-03 structural guarantees with two bash invariant guards (single `stega:false` client; no stega Unicode in the build output) plus a GROQ content-presence check for DE/EN pairs. This is the phase's verification backbone — it makes "Sanity is the only content home" and "no stega corruption" structurally enforced, mirroring Phase 2's build-time discipline.

## Reversibility note

No new one-way decisions here — this plan authors content and adds guards against already-locked decisions. The pricing values are RESOLVED (D-05) and are NOT re-litigated: landing `ab €1.500` (`price.amount=1500`, `priceFrom=true`, `priceOnRequest=false`), full-site tier `priceOnRequest=true` with `price.amount` null.

## Artifacts this phase produces (Plan 03 subset)

- **Files:** `content/brightbyte.ndjson` (canonical seed), `tests/invariants/sanity-single-client.sh`, `tests/invariants/no-stega-in-build.sh`, `tests/sanity/content-presence.mjs`
- **npm scripts (updated):** `test:invariants` (append the two new guards), `test:content` (content-presence GROQ check)
- **Content authored:** DE/EN pairs for two `service` docs (landing + full-site tiers), 3 `testimonial` docs (Blumenspiess +200%, Learnstep 92%, Lumo +47%), `project` docs, the `siteSettings` singleton (contact/legal), positioning copy — all as published Sanity documents
