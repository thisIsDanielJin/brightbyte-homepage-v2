## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted client -> POST /api/contact | Attacker-controlled JSON body crosses into the Route Handler |
| Route Handler -> Resend API | Server-side email send using RESEND_API_KEY |
| Server env -> client bundle | RESEND_API_KEY must NOT cross this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-07 | Information Disclosure | RESEND_API_KEY | high | mitigate | Read only in app/api/contact/route.ts; never imported into a client component or `NEXT_PUBLIC_`-prefixed. Verified by grep in review. |
| T-04-08 | Denial of Service | Contact form flood | high | mitigate | Honeypot + time-to-submit (<3s silent) + per-IP rate limit (429) per D-10 (A6: in-memory acceptable for low-volume solo studio). |
| T-04-09 | Tampering | XSS via form input | medium | mitigate | Zod validates shape; React escapes all rendered strings; email body is plain text, not HTML-interpolated. |
| T-04-10 | Tampering | Bot passing honeypot | medium | mitigate | Time-to-submit check as second layer; rate limit as third layer. |
| T-04-11 | Tampering | Malformed / oversized payload | low | mitigate | `schema.safeParse` -> 400 before any send; no unbounded processing. |
</threat_model>
